# EXP-2026-017: 未知分割・三moduleへの盲目的component移送

状態: confirmation前gate通過、task未実行  
登録日: 2026-08-02  
対応仮説: `H-RC-008`, `H-RC-007`, `H-BIO-004`

## 1. 問い

座標を無作為に並べ替えた三module tanh RNNで、task値を見ずに重みだけから
module分割を回復し、EXP-2026-016の二module用固定predictorを再fitせず適用して、
有限外乱符号記憶をglobal profileおよび孤立task積より正確に較正できるか。

## 2. 検証対象を一軸に限定する理由

本実験は「未知分割」と「module数2から3への移送」を同時に扱うが、確率外乱、
学習中の重み変化、非線形global baselineは導入しない。複数の未検証軸を同時に
変えて失敗原因を識別不能にしないためである。成功しても任意系への一般化とは
扱わない。

- model SHA-256:
  `db0b50a648fb085ca687922a531fab5482af2a134bd01eefc3efe3dd85675a01`
- 再fit、特徴選択、penalty変更: 禁止。
- development seed: 2201–2230。実装testとtask飽和確認にのみ使用する。
- confirmation seed: 2301–2330。過去のpilot/confirmation/development seedと
  重複させない。
- module size: 2+2+3 node、全dimension 7。
- diagonal gain: 1.5。

各module内部は非対称で、全module pairのbridgeも正strengthでは双方向かつ非転置

profile抽出器へ渡さない。

## 4. task前の分割推定

観測重みから

\[
A_{uv}=\max(|W_{uv}|,|W_{vu}|)
\]

を作り、全pair affinityの隣接値間で最大gapを選ぶ。gap中点をthresholdとした
無向graphの連結成分を推定moduleとする。task実行前に、生成時の真値は構造gate
だけで使い、次を要求する。

1. 推定成分数が3、size multisetが `{2,2,3}`。
2. label permutationを除き真の分割と完全一致する。
3. 最小module内affinityが最大module間affinityより大きい。
4. 推定に使ったgapが上のinter/intra gapと一致し、最大gapが一意である。
5. family・gain・strengthごとに30 networkが30絶対値構造classを持つ。
6. 正strengthでは全module pairが双方向に結合する。

一つでも不成立ならtask値を生成せず、family設計失敗として記録する。

## 5. 多成分profile

推定partitionから方向別負荷行列

\[
L_{ij}=\max_{r\in I_i}\sum_{c\in I_j}|W_{rc}|
\]

と総流入 (\ell_i=\sum_{j\ne i}L_{ij}) を求める。局所orthant profileだけから

\[
R_{dir}(e)=\prod_i r_i(e+\ell_i)
\]

を計算する。global、component-aware、product-onlyの特徴名・係数は
EXP-2026-016と同一に保ち、三module値は次の対称集約で定義する。

- isolated task product: codeごとに三局所保持率を積み、その後4 codeで平均。
- isolated certificate product: 三局所認証率の積。
- maximum directional bridge norm: (\max_i\ell_i)。
- directional load imbalance: 
  \((\max_i\ell_i-\min_i\ell_i)/\sum_i\ell_i\)、零負荷では0。
- module size imbalance: 
  \((\max_i d_i-\min_i d_i)/\sum_i d_i\)。
- mean/minimum directional slack: 全直積を作らないsurvival積で厳密計算。

結合後task、transported rectangle、oracle partitionは保証監査にだけ使い、予測
特徴の選択、分割推定、係数には使わない。

## 6. 事前登録判定

toleranceは (10^{-12})、bootstrapはseed単位10,000 resample、95%区間とする。

### 6.1 理論・構造判定

1. `partition_recovery`: 第4節の全構造gateが成立する。
2. `oracle_inferred_equivalence`: oracleと推定partitionの全profile特徴・予測が
   tolerance内で一致する。
3. `zero_coupling_factorization`: strength 0の全点でtaskと三局所code積則が一致。
4. `factorized_certificate_exactness`: 因子化計算した (R_{dir}) と小規模な
   直積列挙値が全点で一致する。
5. `transported_lower_bound`: 全点でtask retentionが
   transported certificate以上。
6. `certificate_chain`: 全点で
   (T\ge R_{rect}\ge R_{dir}\ge R_{global})。
7. `feature_finiteness`: 全特徴とtargetが有限で、target漏洩がない。
8. `complexity_reduction`: 一network当たり局所orthant数が
   (4+4+8=16)、全系128の1/8である。

### 6.2 経験判定

1. 固定component-aware MAEが0.05以下。
2. 固定component-aware Spearmanが0.60以上。
3. seed単位global minus component MAEの95%区間下限が0.005以上。
4. seed単位product-only minus component MAEの95%区間下限が0以上。

順位相関でbaselineを上回ることは登録しない。12判定の一つでも不成立なら、
二module固定predictorの未知三module較正への移送は確認失敗として保持する。
構造・certificate判定と経験predictor判定は別々にも報告する。

## 9. 証拠境界

affinity gapをgeneratorが明示的に持つため、一般のRNNでcommunityを回復できる
ことは示さない。dimension 7の全orthant taskはcertificate監査の参照であり、
人間規模計算自体ではない。人間規模への寄与は、局所次元が有界なら方向別
certificateが (2^n) ではなく 
\(\sum_i2^{d_i}\) で計算できるという構成と、その実装一致に限る。
